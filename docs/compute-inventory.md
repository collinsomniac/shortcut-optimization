## Throughput without invented totals

For a request-capped route, an upper *illustration* at 50 requests/day and 800 input + 200 output tokens/request is **50,000 processed tokens/day**, of which 10,000 are generated. This is an arithmetic scenario for OpenRouter Free, not a token allowance or service guarantee. At 100 requests/day or 2,000 tokens/request it changes proportionally; model context, output caps, RPM, upstream availability and failures can lower the achieved total.

For Supabase's 500,000 Edge Function invocations, dividing by 30 yields about **16,667/day** only as a calendar average. An invocation is not an LLM completion; compute time, memory, quotas and egress constrain useful work. For GitHub Actions public repos, **no fixed monthly minute budget** follows from “free”; runner capacity, concurrent jobs and acceptable-use limits still apply. For Colab, a number of compute units cannot be turned into GPU hours without a specific accelerator's unit rate, region/availability and observed runtime. For ChatGPT Plus and Gemini free API, personalized or model-specific limits prevent a defensible aggregate token total.

For phone inference, `generated tokens = measured decode tok/s × seconds of active generation` and `completion latency ≈ load + prefill + output_tokens/decode_rate`. Example: 20 measured tok/s and 200 output tokens gives ~10 seconds of **decode alone**. Cold load, thermal throttling and app suspension add time. [An E2B native-app benchmark](https://rockyshikoku.medium.com/local-llm-on-iphone-which-runtime-is-actually-fastest-58096685481e) cannot be substituted for E4B in mobile Safari.

**Capacity is not additive across surfaces:** a phone, Colab notebook, static GitHub site, cloud database and an account-level agent limit serve different jobs. Never treat a consumer subscription as authorization to resell or pool compute for third-party repo users. Publish configurations that work with each user's own selected backend and an offline path.

## Account checks to make the inventory exact

1. Google AI Pro billing region/status and Colab Settings → Subscription unit balance and accelerator availability; note rollout date and reset date.
2. Gemini AI Studio project's free tier/model rate limits and whether a billing account is linked. Do not equate Pro app access with API access.
3. ChatGPT/Codex usage screen for the account's current shared limits; API billing dashboard separately if API is ever used.
4. GitHub repo visibility and Actions/Pages usage; Supabase Free organization/project dashboard; OpenRouter account's current model limits and credits.

Store only redacted figures and dates in experiment records, never subscription receipts, tokens, API keys or billing identifiers.
