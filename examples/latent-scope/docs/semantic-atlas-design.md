# Semantic atlas: evidence-bearing streaming interpretation

Research and design note, 24 September 2026. This extends [the interpretability roadmap](interpretability-roadmap.md). The current Latent Scope build observes WebLLM output tokens and up to five rival probabilities; it does **not** receive hidden states. Everything below that depends on hidden states is a proposed experiment, not a claim about the running dashboard.

Implementation update: the separate `atlas.html` experiment now captures a named residual state. See [implementation and validation](activation-atlas-implementation.md). The original WebLLM dashboard still exposes probabilities only. Proposed SAE/probe/causal functionality below remains future work.

## The key distinction

An output embedding of generated text can describe what was *said*. A final-position residual activation at a named layer, collected while predicting the next token, can encode information that is not yet said. An SAE feature is a learned coordinate of that activation, not one weight or one neuron. A feature firing correlates with a representation; a demonstrated contribution to a target choice additionally needs attribution and a controlled intervention. A chain-of-thought string is output text and need not disclose this computation.

Keep three separately labeled lanes in the interface: **said** (visible tokens), **represented** (probes/features measured from hidden states), and **affected this choice** (target-specific attribution or intervention). Never blend the first lane into the latter two with a suggestive color or an unmarked semantic summary.

## Research that changes the plan

| Technique | What it reads | Useful result | Constraint for this app |
| --- | --- | --- | --- |
| Sparse autoencoders (SAEs), Gemma Scope 2 | A named model activation at a particular layer and position | Sparse feature IDs, strengths, candidate natural-language labels | Exact model, hook and dictionary required; reconstruction and label coverage must be measured. |
| Cross-layer transcoders and circuit tracing | Approximate MLP computation with sparse features, then trace a target logit backward | A prompt-specific graph of candidate feature paths, followed by feature interventions | Substantially more compute/storage; replacement fidelity and intervention agreement matter. |
| Tuned lens and Jacobian lens | Intermediate residual states projected to vocabulary or future verbalizable content | Words the model might be ready to express, even when they do not appear in output | Probe predictions are distinct from actual final logits; train and calibrate for the exact model. |
| Natural Language Autoencoders (NLAs) | An activation verbalizer makes text; a reconstructor recovers the activation | Possible textual description of otherwise hidden information | Released checkpoints start at 7B and are expensive; descriptions can hallucinate. No 1B drop-in. |
| Prompt contrasts and activation patching | Same target under matched input interventions | Evidence that a source activation changes a predeclared target logit | Establish controls, seeds and faithful replay; intervention effects are prompt and target specific. |

Anthropic's 2026 NLA work is unusually close to the requested 'translator': activation → text → reconstructed activation, trained on the information preserved by the round trip. Their own account reports hallucinated descriptions and hundreds of verbalizer tokens per readout. Their published open checkpoints cover Qwen2.5-7B, Gemma 3 12B/27B and Llama 3.3 70B, not our Llama 3.2 1B. A phone implementation would need a separately trained, much smaller and validated distillation, invoked only at selected change points. The 2026 Jacobian lens is another direct lead: it projects hidden states through an average input-output Jacobian into words the model may later be disposed to say; its reference code fits open decoder models and shows layer × position readouts. These are promising experimental readouts, not a literal transcript of thought.

Sources: [Anthropic NLA overview](https://www.anthropic.com/research/natural-language-autoencoders), [released NLA code and model list](https://github.com/kitft/natural_language_autoencoders), [global workspace/J-lens research](https://www.anthropic.com/research/global-workspace), [J-lens reference implementation](https://github.com/anthropics/jacobian-lens), [circuit-tracer supported Llama 1B transcoders](https://github.com/decoderesearch/circuit-tracer), [Gemma Scope 2](https://deepmind.google/models/gemma/gemma-scope/), [OpenAI's automated neuron explanations and limitations](https://openai.com/index/language-models-can-explain-neurons-in-language-models/), and [circuit tracing methods and fidelity caveats](https://transformer-circuits.pub/2025/attribution-graphs/methods.html).

## The proposed visual: a growing atlas with token anchors

At the top, retain the reply as readable text with a small cursor on the *decision boundary*. Under it, draw a stable two-dimensional atlas of precomputed feature positions for **one selected layer**. Each node is a feature ID; color means measured activation above a reference distribution and halo means repeated appearances in this run. Connections are labeled co-activation, temporal succession, estimated attribution, or intervention-supported influence. A low-dimensional layout is a navigation aid: distances, isolated islands and lines do not prove semantic or causal relationships. Show the corresponding layer and hook prominently; do not put features from incompatible layers into a common metric map.

A compact 'idea ledger' beside or over the map groups validated features by provisional label, with **first seen / most recent / strongest token / prompt or generation / number of positions**. Tapping an idea highlights its entire per-token sparkline and the exact text span. Tapping a token pins the pre-decision model state, top SAE features, any probe words, chosen and rival token probabilities, and a link to the feature's examples, counterexamples and evidence. Pinned inspection is inert while the live stream proceeds. The atlas accumulates occurrences, but offers an explicit recent-window filter so a common early feature cannot drown later changes.

Do not add hidden-state vectors or token embeddings into a single 'semantic sum'. Averages can cancel or swamp transient and opposing evidence; residual states change meaning by layer, position and context. Store a sparse event sequence instead: a(t, layer, feature), the reference-normalized excess over matched baseline, and run-local count/maximum/recent value. Group contiguous subword tokens into a visible text span while retaining exact token indices underneath. If the atlas needs a scalar intensity, use a clipped, baseline-normalized recent activation and a separately labeled persistence measure. Preserve signed target contribution as a different measurement.

Examples: for OCR → Markdown, a *validated* feature might reflect table structure or code formatting before its first visible markup token; for a vegetable cream cheese recipe, a feature might reflect ingredient ratios or sequencing before the corresponding sentence. These are hypotheses to test on matched prompts and negative controls. If the only evidence is that those words later occur, label it as output-derived topic, not internal prediction.

## Capture and alignment

1. Keep the current production WebLLM chat/probability path working. Its public chat API returns token log probabilities, and the app currently gets no hidden-state callback. A logits processor is not a residual-stream hook.
2. First run an **offline exact-model pilot** with a standard unquantized Llama-3.2-1B-Instruct checkpoint, named residual hooks at a few layers, and a compatible existing 1B SAE or transcoder. The Aquin Labs 1B-Instruct SAE set reports 16 layers, width 32,768 and about 8.1 GiB total; sample *one layer* and verify hook conventions, feature examples and reconstruction. The circuit-tracer project also lists Llama-3.2-1B transcoders. Check checkpoint, tokenizer, chat template, layer and probe revision before combining either with our quantized MLC model.
3. Record each prompt position during prefill and each model state *before* it predicts a generated token. The state at context position t predicts token t+1; when annotating a chosen token, preserve this offset. Record actual token IDs, not only rendered chunks, and inspect the final generated position separately when useful.
4. For live phone activation capture, create a pinned, instrumented MLC model/runtime build with a named, small tap after selected residual blocks. Compute SAE scores and top-k on GPU if feasible, then transfer only IDs, scores and quality counters. Do not pull full layer matrices to JS every token or pretend a separate PyTorch run is live phone telemetry. A second model checkpoint or incompatible quantization goes in a separately labeled **offline replay** mode.
5. Put generation in a worker and send a compact event per decoding step to the UI. Keep raw trace events separate from display frames. Batch texture uploads, cap canvas pixel ratio, update labels at most a few times per second, and degrade visual frame rate under load without dropping inference events. If telemetry is lost, show a gap rather than interpolated 'activations'.

Example event fields: schema version; model/runtime/quantization/tokenizer/probe hashes; phase; context position; predicted token position; generated token ID and text; hook/layer; sparse feature IDs, raw strengths, baseline-normalized strengths and SAE reconstruction metric; candidate logits or probabilities; timing; sampling/drop counters. For attribution, record the *target token or logit difference* and separate method and intervention result. Version the local feature catalog by all of the above plus label revision and examples.

## Validation before calling a node an idea

Use both suggested tasks plus at least one paraphrase and one contrast for each. For OCR, compare table versus paragraph, OCR versus handwritten transcription, and Markdown requested versus plain text; for the recipe, vary vegetables, serving size, and whether the task is cooking or shopping. Register target decisions in advance (for example, probability of a Markdown table delimiter or a particular recipe step), inspect highest activating input/generated contexts and held-out negatives, then ablate or patch candidate features and compare target logit differences. Report change in probability and any side effects. Validate reconstruction error, feature stability across repeated prompts, and whether labels predict held-out firings. A good label is a falsifiable hypothesis, not a feature name bestowed by an explainer.

Ship threshold: useful hidden-state signals must beat a text-only and token-logprob baseline on held-out contrasts, have measured intervention support for claims of contribution, maintain responsive mobile interaction, and explicitly disclose incomplete dictionary coverage. Until those gates pass, the current app should keep its honest 'observed output' view while offline replay experiments can populate the atlas with clearly identified research traces.
